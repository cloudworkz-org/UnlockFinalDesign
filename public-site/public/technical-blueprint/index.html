Technology blueprint

How Unlock works.

A walk-through of the architecture, security and calculation design behind Unlock, in the order a piece of data travels: where it starts, how it is protected, how it is calculated, and where the boundaries are.

The core idea

The desktop app does the work, the cloud keeps encrypted copies, and the phone shows the result.

Unlock is designed local-first. The system of record sits on the user’s own computer, so platform logins and raw records are designed not to sit in a central database.

The desktop app

The system of record lives on the user’s own machine.

Signs in

Logs in to each supported platform from the user’s computer, as the user would.

Extracts

Reads holdings, valuations and account information.

Stores

Keeps everything in an encrypted local database.

Calculates

Runs the analytics and planning engines on the desktop.

Designed to keep working with no internet connection. Sync to phone and web is optional.

Getting data in

Four routes in, one investor record.

PLATFORMS

Platforms without a feed: the desktop app signs in and the data stays on the device.

CONNECTIONS

Banks and government services: a connector fetches with the user’s consent and seals the result to the desktop.

DOCUMENTS

Statements and spreadsheets: read, mapped and checked, with the user confirming.

MANUAL

Property and private shares: typed in by the user.

The investor record is one picture of everything the user owns and owes. Every tool reads it.

The engines

Three engines, each with its own method.

EIS and SEIS modeller

Models an illustrative multi-year programme from income and the cash the investor chooses to deploy. A repeatable simulation shows a range of outcomes for illustration.

Investor persona

Reflects the investor’s answers back as a closest-match portrait, for understanding rather than recommendation.

Retirement planner

Works year by year, with spending, tax and drawdown order, to illustrate how a plan could play out.

How the tools connect

Tools share one record, tax tools one rulebook.

One investor record

Assets, liabilities, income and goals. Every tool reads from it, so a change made once shows up everywhere.

One rules knowledge base

Tax, allowances and relief rates, kept up to date and shared by the tax tools, so they work from the same rules.

Signing in to platforms

Logins stay on the user’s computer.

1 · The userEnters the login once and approves two-factor if asked
→
2 · The appSigns in through the platform’s own page, or its API
→
3 · The platformSees a sign-in from the user’s own device and network

The login is held in the credential store on the computer. It is designed so that it is not sent to Unlock’s cloud; only a summary of holdings and values goes onward.

Keys, sync and the phone

Designed so only ciphertext is stored in the cloud.

1The desktop creates a data key, locked by a secret the user holds
→
2The user pairs the phone with a one-time code
→
3The desktop encrypts each snapshot before it leaves the computer
→
4The cloud stores the encrypted copy
→
5The phone downloads and decrypts it locally

A printed recovery key opens the encrypted backup if the computer is replaced.

Protecting credentials

Four layers, working together.

Tokens, not passwords

Keeps a session token where the platform allows.

Operating system protection

Credentials are held in the computer’s built-in secure storage.

A secret only the user holds

Unlocks the credential store for a session and relocks it on logout or when idle.

Encrypted database

The local holdings database is encrypted.

Credentials are designed to be left out of sync and logs.

Boundaries

Read-only, by design.

Holds no money

Assets stay with the platforms that hold them.

Does not trade

Designed with no way to place orders or move funds.

Reads only

It does not change accounts. Disconnecting stops the refresh.

Information and illustration

Structured decision support, built for understanding rather than instruction.
